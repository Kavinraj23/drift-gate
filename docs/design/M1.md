# M1 design note: synthetic generator, repos, ground truth

## What was built

`python tasks.py data` runs `python -m driftgate.generator` (seed 20260908, anchor 2026-09-08, 30 days) and writes a validated dataset to the gitignored `data/`:

| Path | Content |
| --- | --- |
| `manifest.json` | neutral only: seed, anchor, days, stats, pipelines (name, ecosystem, refs, cadence; no flaky flag), file pointers |
| `executions.json` | about 1360 executions over 12 pipelines, using the domain `Execution`/`Node` shape (stage and step tree, failed leaf has `error_summary`), `refs`: connector, template@version, runner_pool, infra_def, commit, optional retry_of |
| `changes.json` | change timeline (commits with shas, template releases, connector, runner pool and config changes); about 240 entries, most with no causal link |
| `logs/<exec>/<node>.log` | GitHub Actions raw-log-shaped failed-step logs (timestamps, `##[group]`, Terraform box blocks, optional ANSI) |
| `repos/<pipeline>/main/...` and `repos/<pipeline>/<sha>/...` | real files per pipeline (workflow YAML, lockfile, tf, requirements). The failing execution's `refs.commit` points at a snapshot holding the injected fault |
| `world/followups.json`, `world/rerun_logs/` | simulator-internal: world response for M4's SyntheticTarget (what a rerun yields, hashes of corrected files). Not agent-visible; see residual risk below |
| `ground_truth/labels.json`, `scenarios.json`, `catalog_use.json` | labels, scenario ids with the held-out partition, and which catalog entries produced each log. Read only by `eval/ground_truth.py` |

Code lives in `src/driftgate/generator/`: `pipelines` (fleet), `faults` (fault families and their labels), `repos` (file builders, fault injection, diffs), `catalog` + `error_catalog.json` (verbatim strings with `source`), `logs` (rendering), `population` (pure `generate(seed)`), `writer` (write and JSON Schema validation), `schemas/` (our own schemas; `contracts/` untouched). `src/driftgate/eval/ground_truth.py` is the single reader.

Population: ~80% success; failures are filled by class quota (60/25/15 user/platform/transient), with specials counted first. Four bursts (template v2.1.0 on 5 tf pipelines, expired token on connector aws-prod, OOM on pool-small, throttling on connector aws-shared), each inside a 20-minute window with a causal change event shortly before and a decoy change nearby. Two flaky canary pipelines fail about 10% of runs and each failure is followed by a passing retry. Transient failures elsewhere are followed by a passing rerun 50-75% of the time, which creates flake precedent for some fingerprints and not others. Three approval rejections. Two wrong-first-fix cases: the log shows `ThrottlingException` first, then the state lock; a Tier 0 rerun fails with the lock error only (`followups` points at a `.rerun.log`).

Ground truth per failure: layer, classification, disposition (remediate / escalate / close), correct tier and action, tier0 path, whether flake precedent exists in the data (computed from the data, not assumed), fleet-wide flag, blast radius, causal and decoy change ids, fix diff and paths for Tier 3, first-fix-fails flag, catalog ids, scenario id.

## Why these choices

- **Pure `generate(seed)`** returning `{path: text}`: determinism is a byte-equality test; the CLI only writes. All randomness is `random.Random` seeded from `"{seed}:{label}"` sub-streams, so adding a feature in one phase does not reshuffle another.
- **Quota-based failures** rather than per-slot coin flips, so base rates land inside tolerance by construction.
- **Precedent is computed**: a flake-precedent fault with no earlier fail-then-pass for the same pipeline and fault is labelled `escalate` (invariant 3). Fleet-wide bursts are always `escalate` (invariant 5), with the ideal fix still recorded.
- **Snapshots per failing execution** instead of real git history: simple, deterministic, and `read_file(repo, path, ref)` maps to a directory. Cost: faults are not persistent in the repo (the next execution is back on `main`).
- **Catalog-only log text** (invariant 9): `test_logs_contain_only_catalog_text` re-renders each log's catalog uses and asserts the log lines equal them exactly, so no free text can enter a log. Run-specific placeholders (lock ids, paths, hosts, operation names) are the only generated parts.
- **Ground truth isolation**: written under `ground_truth/`; a test scans every agent-visible file (everything outside `ground_truth/` and `world/`) for label keys, `flaky`, `held_out`, scenario ids and catalog ids; the architecture test already forbids the string `ground_truth` outside `eval/` and `generator/`; a new AST test forbids any import of `driftgate.eval` or `driftgate.generator` by other modules.

## Tested

`tests/generator/test_generator.py` (offline, ~0.3 s per generation): same-seed byte identity, different-seed difference, 12 pipelines over about 30 days, base rates within tolerance, bursts (3-4, >=3 members, within 20 minutes, shared ref), flaky pipelines have >=3 fail-then-pass retry pairs, decoy changes exist, scenario family coverage and 8-10 held out, Tier 3 failures have snapshots and fix hashes, the lockfile fault is really out of sync, every catalog entry has a source, logs contain only catalog text, no label keys leak into agent-visible files, import isolation, schema validation round trip through the eval reader, schema validation rejects bad data.

## Changes to existing tests

`tests/test_tasks.py::test_not_implemented_target_exits_1` used `data` as its example of an unimplemented target. `data` is now implemented, so the test uses `baseline` (M3), which keeps the identical assertion on the not-implemented path. Justification: an assertion that an unimplemented target exits 1 needs an unimplemented target, and `data` stopped being one when M1 landed; the assertion itself is unchanged. PROGRESS.md needs the justification line (orchestrator).

## Open doubts

- Several recalled strings could not be confirmed offline (see BLOCKERS.md, Needs human). The block shapes and wrap points are from memory of widely-posted output.
- Residual risk in `world/followups.json` (round 1 review). It is simulator behaviour and cannot be removed, since a rerun of a transient failure must pass and a Tier 3 fix must be checkable. Mitigations: it lives under `world/`, away from all agent-readable data; every failure has the identical key set (`rerun{status,log}`, `fix_applied{status,accepted_files}`), so key presence reveals nothing; the second-attempt rerun log sits at `world/rerun_logs/<exec>.log`, not next to the agent-visible logs; a test fails if any module other than `generator/`, `eval/` and `adapters/synthetic*` mentions `followups` or the `world` directory. What remains: the values themselves (rerun status, non-empty `accepted_files`) encode the transient/Tier 3 distinction, so any future code that exposes this file to an agent breaks the eval. M4 must read it only inside SyntheticTarget.
- Error catalog (invariant 9): no string is a captured verbatim sample. Every entry now carries `verified: false` and `source_kind` (`recalled-from-widely-posted-output`); a test requires both fields and forbids the old "copied from real tool output" claim. BLOCKERS.md lists the entries a human must check against real output.
- Execution statuses are lowercase `success` / `failed` / `approval_rejected`, and node statuses `success` / `failed` / `skipped` / `rejected`. `domain.py` does not constrain them; M3 should confirm or map.
- Accepting a Tier 3 fix by exact file hash rejects any other valid fix. Fine for the offline eval, strict for PR-quality scoring.
- Failures are drawn per slot, so a user fault (for example a bad lockfile) is not persistent across runs. Realistic persistence would make duplicates and fingerprints more interesting; left for later.
- Scenario sampling keeps 34 scenarios; held-out ones are the last instance of 9 randomly chosen multi-instance families, so held-out cases share templates with dev cases by design. The PRD asks for unexamined scenarios, not unseen families.
