# M2: LLM gateway

## What was built

All under `src/driftgate/llm/`. Only `gateway.py` imports the Anthropic SDK, and it does so lazily inside `_make_sdk_client`, so importing the module, replay mode, and every test never load the SDK.

| Module | Responsibility |
| --- | --- |
| `gateway.py` | `Gateway` (implements `ModelClient`), `BoundClient`, payload building with `cache_control`, retries, SDK response parsing, record/replay dispatch |
| `config.py` | `GatewayConfig`, price table, `estimate_cost`, `InvestigationLimits`, `config_from_env` (pure) and `load_config` (the only place `python-dotenv` is used; never called by tests) |
| `limits.py` | `TokenBucket`, `RateLimiter` (requests/min + tokens/min), `ConcurrencyLimiter` |
| `ledger.py` | `SpendLedger`: SQLite, one connection per operation, UTC-day buckets |
| `budget.py` | `InvestigationBudget`, `CallRecord`, `run_fields()` for the Report `run` object |
| `replay.py` | Request normalization, key derivation, `FixtureStore` (stdlib only) |
| `clock.py` | `Clock` protocol (`time`, `monotonic`, `sleep`) and `SystemClock` |
| `errors.py` | `BudgetExceeded`, `InvestigationBudgetExhausted`, `RetriesExhausted`, `FixtureMissing`, `UnknownModel`, `MissingApiKey` (all `GatewayError`) |

`llm/types.py` gained two defaulted `Usage` fields (`cache_read_tokens`, `cache_creation_tokens`), backward compatible with `FakeModel` and existing tests.

### Using it

```python
gw = Gateway(config, mode="live" | "record" | "replay", fixtures=FixtureStore(dir))
budget = InvestigationBudget()           # 8 tool calls, 40k tokens, 1 re-investigation
client = gw.bind(budget, role="investigator")   # or "reviewer"; drop-in for FakeModel
client.complete(request)
budget.consume_tool_call()               # False -> agent abstains, sets budget_truncated
budget.begin_reinvestigation()           # False -> escalate
budget.run_fields()                      # {"tool_calls","input_tokens","output_tokens","cost_usd","latency_s"}
```

`request.model` empty means the role's configured model (`DRIFTGATE_INVESTIGATOR_MODEL` / `DRIFTGATE_REVIEWER_MODEL`, default `claude-haiku-4-5-20251001`). The token budget is checked before each call (`InvestigationBudgetExhausted`); tokens count input, output and cache tokens. `Gateway.complete` without `bind` behaves as an unbudgeted investigator-role call.

## Behavior

- **Order of a live call:** reserve worst-case cost against both caps (fail fast, no limiter wait, no network) -> rate-limit acquire -> concurrency slot -> send with retries -> compute cost from `usage` -> write ledger -> release reservation -> log.
- **Caps:** lifetime $2.50 and daily $1.00 (UTC day), configurable. A call is refused if `spent + in-flight reservations + worst case (estimated input tokens + max_tokens at output price) > cap`. Conservative by design; this means a nearly full cap can refuse calls that would actually have fit.
- **Retries:** status 429 and 529 only (duck-typed on `status_code`, so no SDK exception import). Delay = `max(base * 2**attempt capped at 60s, retry-after)` plus jitter of up to 25% of the backoff. The SDK's own retries are disabled (`max_retries=0`) so the limiter and logs see every attempt. Failed calls cost nothing in the ledger.
- **Caching:** the system prompt becomes a text block with `cache_control: ephemeral`; the last tool definition carries `cache_control` (one breakpoint caches the whole tool prefix). The caller's request object is never mutated. Cache read/write tokens are priced with multipliers (default 0.1x and 1.25x of the input price).
- **Rate limits:** defaults 40 requests/min and 40k tokens/min (`GatewayConfig`; set below the real tier limits when the human knows the tier). Tokens are reserved at estimate + `max_tokens`, and the unused output portion is refunded.
- **Logging:** each call appends a `CallRecord` (tokens, cost, latency, limiter wait including retry sleeps, mode) to `gateway.calls` and to the bound budget.

## Fixture layout and key derivation (for the human-run `record` target)

```
<fixture_dir>/<key>.json
```

`key` is the lowercase hex SHA-256 of the canonical JSON of the **normalized request**:

```
{"model": <resolved model>, "max_tokens": int, "system": str, "tools": [...], "messages": [...]}
```

serialized with `json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=False)` and UTF-8 encoded. The model is the request's model or the role default, so changing the configured model changes the key. Cache markers are not part of the key. Anything that alters the system prompt, tool schemas, messages or `max_tokens` therefore invalidates fixtures; re-record after prompt edits.

File content:

```json
{
  "fixture_version": 1,
  "key": "<same as filename stem>",
  "request": { "...normalized request, for human inspection and debugging..." },
  "response": {
    "text": "...",
    "tool_calls": [{"id": "...", "name": "...", "input": {}}],
    "usage": {"input_tokens": 0, "output_tokens": 0, "cache_read_tokens": 0, "cache_creation_tokens": 0},
    "stop_reason": "end_turn"
  }
}
```

Record: `Gateway(config, mode="record", fixtures=FixtureStore(dir))` runs the full live path (caps, limits, ledger) and saves each response. Replay: `mode="replay"` reads files only; it constructs no client, ledger, limiter or clock, needs no API key, and raises `FixtureMissing(key, path)` when absent. Replay logs an estimated cost from the recorded usage (not charged to the ledger) so the eval can report cost. The `record` target itself is not implemented here (human-only, M5).

## Tested (`python -m pytest -q tests/gateway`, 31 tests)

Token bucket and two-bucket limiter on a fake clock; concurrency cap with real threads (events, no sleeps); daily cap, next-day reset, lifetime cap, restart persistence, worst-case reservation; fail-fast before network (stub records zero calls); 429/529 retry with retry-after and exponential backoff on a fake clock, retries exhausted, non-retryable passthrough, no ledger entry on failure; cache markers present and request not mutated; cost with cache multipliers; unknown model fails closed; per-role model selection; lazy client factory; investigation budget exhaustion and `run_fields`; tool-call and re-investigation limits; record -> replay round trip via a stub SDK client; missing fixture typed error; key stability; subprocess checks that replay and merely importing `gateway` never import `anthropic` (even with sockets blocked).

## Open doubts

1. **Sonnet 5.5 prices** in `DEFAULT_PRICES` ($3 / $15 per MTok) are an estimate; verify against the price page before any demo spend. The cap math depends on this table being right.
2. **Rate-limit defaults** (40 rpm, 40k tpm, concurrency 2) are placeholders until the account tier is known.
3. **Token estimate** is chars/4, deliberately rough; the worst-case reservation may refuse a call slightly early near a cap.
4. **Duck-typed SDK shape:** responses and errors are parsed by attribute (`content`, `usage.cache_*_input_tokens`, `status_code`, `response.headers`). Tests use a stub in that shape; the first live record run is the real check. Not verified against the live API (not permitted autonomously).
5. **Daily window** is the UTC date, not the human's local day.
6. **Replay and budgets:** replay does count tokens against the per-investigation budget (so budget behavior matches live), which means fixtures recorded with large usage will truncate the same way.
7. The `Usage` dataclass change touches a shared file (`llm/types.py`); additive only.
