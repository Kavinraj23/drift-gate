### SyntheticSource
Reads only `executions.json`, `changes.json`, `logs/` and `repos/` of a dataset directory. Every read goes through `_resolve`, an allowlist of those four top-level entries that also rejects absolute paths, `..` and symlink escapes. The simulator-only and label directories are therefore unreachable by construction, not by convention. `manifest.json` is not read either. Statuses are confirmed as lowercase `success` / `failed` / `approval_rejected` (execution) and `success` / `failed` / `skipped` / `rejected` (node); constants are exported and a test pins them. `list_executions(window, filter)`: `window` is `(start, end)` (ISO or datetime, inclusive) and `filter` is a dict of `status`, `pipeline`, or any `refs` key. `list_changes` is extra (for the stretch `changes_in_window` tool).

### Tools
Each returns a JSON-serializable dict. The dispatcher wraps it in `ToolResult(source=call_id, tool, ok, data, error)`; `source` is the id the caller supplies (the investigator will use the model's `tool_use` id), which is what evidence must cite (invariant 7). Bad tool names, bad arguments (validated against the tool's JSON Schema) and `SourceError`/`ValueError` become `ok=False` results, never exceptions into the loop. Tools take an injected `ToolContext(source, attempts)`; `tools/` imports no adapter, target, `llm`, `eval` or `generator` (tested by AST and by a text scan for write/exec calls).

- **Signatures** are regexes over text that appears in the error catalog entry of the same id (not new error strings), with layer, classification, whether a Tier 0 known-transient rule exists (throttling and registry rate limit only), and a rank. A bare `Process completed with exit code N` is its own signature `exit_code_nonzero` with `deterministic_match=false`: it names no cause. A test renders every catalog entry and asserts it matches exactly its own signature.
- **Fingerprint** = first 16 hex of SHA-256 over `signature_id|pipeline|step`, each part lowercased and whitespace-normalized.
- **Failure analysis**: signature of the failed leaf step, taken from the full step log (fallback to the node's error summary); where several signatures appear, the highest rank is primary (the state lock outranks the throttling that masks it).
- **fleet_correlate**: same-primary-signature failures within +/-30 minutes sharing a connector, `template@version`, runner pool or infra def. Fleet-wide means 3+ executions across 2+ pipelines. The window is symmetric because an investigation can happen any time after the first failure and late and early burst members must agree on the count. Ties between dimensions are broken by failing share, then dimension order; all dimensions are returned.
- **flake_history**: earlier failures with the same fingerprint whose retry (`refs.retry_of`) passed, counting only retries that started before the current execution.
- **get_step_logs**: failed leaf only (a non-failed node is refused). Pipeline: strip ANSI, last carriage-return frame, drop timestamps, redact, collapse spinner frames and consecutive near-identical lines, segment into error blocks (terraform boxes whole; other runs of error-ish lines), merge identical blocks with a count, rank by signature rank (generic exit line last), render under a character budget (default 4000, hard max 8000) with explicit truncation markers. If no error block is found, the log tail is returned. All blocks are returned, not only the first.
- **Redaction** covers AWS key ids, GitHub tokens/PATs, Anthropic and Slack keys, JWTs, bearer/basic headers, URL credentials, PEM private keys and `password|token|secret|api_key|...=value` forms. `read_repo_file` redacts too. A test asserts the dataset's logs contain no `[REDACTED]` (so catalog text is never eaten).
- **read_repo_file**: `repo` is the pipeline name, `ref` is a sha or `main`; default cap 6000 bytes, hard cap 20000.
- **get_remediation_attempt**: reads an injected in-memory `AttemptStore` by fingerprint or attempt id.

### Pre-filter
`prefilter(execution) -> PrefilterResult(closed, report, reason)`, keyed on `execution.status` only: `approval_rejected` / `approval_expired` close as governance L5; `aborted` / `cancelled` close as user L5. The result is a schema-valid `Report` with no remediation and zero run stats. It imports nothing from `llm`; a test pins that. The generator emits only `approval_rejected`; the other statuses are mapped from the PRD wording and unit tested with constructed executions.

### Baseline
`run_baseline(ctx, execution_id)`: pre-filter, then `classify_signature`, `fleet_correlate`, and `flake_history` only when the signature is transient/unknown with no Tier 0 rule. Through the same dispatcher as the agent, so its evidence cites real call ids (`<exec>:baseline-N`).
Rules: fleet-wide gives escalate (a user-class signature repeated across pipelines on one dimension is reclassified platform); Tier 0 rule gives Tier 0 re-run; transient/unknown with flake precedent gives Tier 0; everything else escalates. It can only propose Tier 0: it cannot author a diff, so Tier 3 cases are missed by design. Its Tier 0 proposals carry `gate_decision="allowed"` as a pre-gate default; the baseline does not run SafetyGate (the eval is of classification and decisions).

### Scoring
`eval/baseline_score.py` runs the baseline over every labelled failure and reports, for all failures, dev scenarios and held-out scenarios: classification accuracy, layer accuracy, remediate/escalate decision accuracy, would-remediate count, false remediations (acted where the label says escalate or close) and rate (over cases the label says not to remediate), remediation recall, tier agreement (effective tier, `None` for escalate/close), blast-radius accuracy (affected count and dimension kind), and tool calls. `python tasks.py baseline` generates `data/` first if missing, then prints the table.

All 22 false remediations are the same case: a generic `npm test` failure (`user_script_failure`) on one of the two flaky pipelines, which is indistinguishable from the flaky-test failure by signature or fingerprint, so the baseline sees precedent and re-runs. The missed remediations are the 87 Tier 3 repo fixes (lockfile, provider pin, undefined variable, pip pin), which a deterministic classifier cannot write. These are the gaps the agent is meant to close.

## Open doubts
- Signatures are derived from catalog text, and the catalog is itself unverified (BLOCKERS.md, M1). If a real error differs in wording, the regexes need updating along with the catalog.
- Governance logs do not exist, so the pre-filter keys on status only. `approval_expired` and `aborted` are mapped, not observed.
- The 30-minute window is symmetric around the failure start; the PRD says "in the last 30 min". A strictly backward window would give the first member of a burst a count of 1.
- Dimension ties (a burst on `runner_pool:pool-small` also shares a connector among the same node pipelines) are resolved heuristically; the scorer compares the dimension kind to any best-tied dimension in tests but reports only count-plus-kind in the table.
- Fingerprint is per step, so a recurring failure of the same step in a different pipeline has a different fingerprint; flake history is therefore per pipeline.
- `get_step_logs` drops timestamps to save budget. The text is otherwise verbatim.
- The baseline's Tier 0 gate_decision is a placeholder; M5/M7 should run it through SafetyGate if it ever acts for real.
