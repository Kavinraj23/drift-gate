# M4: SafetyGate, audit log, SyntheticTarget

## What was built

- `gates.py`
  - `SafetyGate.decide(proposal, GateFacts) -> GateDecision`. The result carries a copy of the proposal with only `gate_decision` changed (`allowed`, `downgraded` or `refused`). The tier is never altered, and `effective_tier` is the proposed tier or `None` (escalate).
  - `KillSwitch` reads `config/kill_switch.json` (path injectable) on every decision. A missing or malformed file fails closed (refused).
  - `RateLimiter`: sliding window, 2 allowed attempts per fingerprint per hour, injected clock. Only `allowed` decisions consume budget.
  - Abort ceiling: refuses an empty proposed set and any action touching 100% of a resource set. Blast radius over N (default 10) and more than one distinct shared resource are downgraded to escalation.
  - Tier 0: needs a signature match AND (flake precedent OR known-transient rule). `prior_tier0_failed` refuses (hard escalate).
  - Tier 2: refused if the holder is running. Otherwise it needs holder `dead` with proof and a successful dry run, else it is downgraded. Allowed means "proceeds to dual approval".
  - Tier 1 and 3 are allowed once the shared checks pass (their own gates are approval or PR).
  - `Step`, `additive_before_subtractive_violations` and `order_additive_first` for multi-step remediations (invariant 13).
- `audit.py`: append-only JSONL `AuditLog` (injectable path and clock). Kinds: proposal, gate_decision, execution, verification, rejected, expired, failed, budget_truncated. No update or delete API.
- `adapters/synthetic.py`: `SyntheticTarget` (dry_run/execute/verify) with per-action `SimulatedOutcome` injection and a simulated `LockTable` with holder liveness. `force_unlock` independently refuses a non-dead holder. `SyntheticSource` is left for M1/M3.
- `config/kill_switch.json` with everything enabled; `M4` added to `IMPLEMENTED_MILESTONES`.

## Why

Eligibility is re-derived from deterministic facts. `GateFacts` has no confidence field that influences decisions (`agent_confidence` is only echoed into the decision for the audit trail). Refusal means a hard stop (kill switch, rate limit, running holder, empty/100% set, post-retry failure). Downgrade means "not eligible, escalate to a human".

## Tested (`tests/gates`, 25 tests)

Kill switch global and per tier, re-read on every call, fail closed; abort ceiling; rate limit on a fake clock; both Tier 0 paths and the ineligible cases; a seeded randomized downgrade-only property test (tier unchanged, only `gate_decision` differs, Tier 0 and Tier 2 allowed only with their facts); Tier 2 refusals; additive ordering; audit completeness and append-only behavior; SyntheticTarget behavior including the Protocol fit.

## Open doubts

- The PRD gives no value for N in "blast radius over N executions". I used 10, a constructor parameter, and it needs a decision.
- The gate decides, and the rate-limit window is in memory. The orchestrator must keep one `RateLimiter` per process, or seed it from the audit log, to survive restarts.
- Gate/tier mismatch (e.g. a Tier 0 proposal carrying `pull_request`) is downgraded. The PRD does not specify this.
- "More than one shared resource" is modelled as the count of distinct names in `shared_resources`. Computing that list is the caller's job (M3/M5).
- The per-process attempt count is recorded at decision time, not at execution time, so an allowed-but-never-executed Tier 1/2 proposal still consumes budget.

## Review-fix round (reviewer findings 1-6)

- `decide` is downgrade-only by construction: an incoming `gate_decision` other than `allowed` is never upgraded (rank order allowed < downgraded < refused; the stronger of incoming and evaluated wins; unknown values fail closed to refused). Non-allowed results consume no rate-limit budget.
- The property test now draws random incoming decisions and asserts the output is never weaker, the tier never rises, and kill-switch-off, missing set facts (tiers 0-2), blast ceiling and multi-resource each imply not allowed, across tiers 0-3.
- `SyntheticTarget.dry_run`/`execute` return a failed result when `gate_decision != "allowed"` (invariant 1, defense in depth).
- Abort ceiling fails closed: for tiers 0-2, `proposed_set_size` or `resource_set_total` of `None` downgrades with reason "set size unknown". Tier 3 keeps the old behavior (checks run only when facts are present).
- Rate-limit tests now cover tiers 0-3 with fake-clock window rollover.
- `AuditLog` keeps a `seq` counter initialised once at construction (still append-only); `record_decision(audit, decision, fingerprint, execution_id)` writes a `gate_decision` entry.

Test-fixture changes (additions only, no assertion loosened), justified by the fail-closed rule: the `facts()` helper in `test_gates.py` now supplies `proposed_set_size=1, resource_set_total=5`; the Tier 2 `ok` fact dict and `test_tier2_running_holder_refused_even_with_everything_else_true` gain the same two facts (otherwise they are downgraded earlier, before the running-holder refusal under test).

Open doubt for the human: for Tier 3 the effective gate is the PR plus reviewer, so missing set facts do not block it. Confirm this is acceptable or require the facts for Tier 3 too.
