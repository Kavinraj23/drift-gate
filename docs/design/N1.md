# N1: Real-log holdout (offline half)

Status: the offline machinery is built; the milestone is **not done** because the data does not exist. The box in
TASKS.md stays unticked until a human has chosen, fetched and labelled the 30 runs.

## What was built
- `contracts/holdout.schema.json` (new; existing contracts untouched). Root = the labels document. `$defs` hold the case
  record and the run-record document (`holdout/runs.json`). A case has: id (`hc-NN`), split (dev|test), layer
  (L0..L6, so governance/never-started escalations fit), classification (the report enum), `correct_action`
  (`rerun` | `pr_fix` with a required named `fix` | `escalate`; `fix` is forbidden otherwise), one-line rationale,
  source (repo, run id, job, commit SHA, URL, fetch date), `log_sha256`, `labeled_at`, plus the doc `schema_version: 1`.
- `holdout/` at the repo root: `README.md`, `labels.json` (empty cases), `runs.json` (empty), `logs/` (log text lives
  only here, one file per case).
- `src/driftgate/eval/holdout.py`: load, validate, quotas, label timing, sealed test split.
- `src/driftgate/eval/holdout_eval.py`: offline scoring and the CLI. `tasks.py` gained `holdout-validate` and
  `eval-holdout` (removed from `NOT_IMPLEMENTED`); `holdout-fetch`, `eval-retrieval`, `approvals`, `trace-report` remain stubs.

## Decisions
- **Labels before runs** is made checkable without a trusted clock: each run record carries `ran_at` and
  `label_sha256` (a digest of the case's label record). Validation fails if `ran_at <= labeled_at`, or if the label
  was edited after the run (digest mismatch, which voids the run). `labeled_at` must not be in the future (injected
  clock) nor before the log's fetch date. This is tamper-evident, not tamper-proof: someone who edits both the label
  and the run record defeats it. Git history is the real backstop (commit labels before runs).
- **Sealed test split in code**: `Holdout.test_cases()` and `case()`/`dev_log()` on a test id raise `SealedSplitError`;
  the only door to test cases is `test_aggregate(scorer, aggregate)`, which returns just the aggregate. Python cannot
  stop someone reading the files off disk; this stops accidental per-case output, and tests assert the CLI output
  contains no test ids or rationale. Schema error messages never echo values (keyword and path only).
- **Id-only rule (round 2)**: every validation message about a test-split case contains only its opaque id (`hc-NN`, so the human knows which stored log to fix) and a generic category, never source, rationale, log text or any label field. Duplicate-source problems list case ids and show the source only when the whole group is dev. Impossible dates (month 13 passes the schema pattern) are reported as problems by id, never raised or echoed.
- **Label immutability**: the real guarantee is git history (labels committed before runs). In-file digests are tamper-evident only. As a tripwire, `holdout-validate` warns (never fails) when `labels.json` has uncommitted changes while `runs.json` is non-empty (`git status --porcelain`, no network).
- **Redaction check**: a stored log must satisfy `redact(text) == text`.
- **Baseline on a lone log**: `signatures.match_all` over the log text; re-run only if the top signature is
  deterministic and has an authored Tier 0 rule (invariant 3; no flake or fleet history exists for a stored log);
  otherwise escalate (the baseline cannot author fixes).
- **Agent column** comes only from `runs.json` run records. Nothing in this milestone runs the agent on holdout logs:
  that needs a holdout source adapter plus recorded fixtures (human-run `record`). Cases without a run show `not run`.
- Quotas are checked on all stored cases; with some cases present but quotas unmet, `eval-holdout` still scores them
  and prints the unmet quotas after the table. Structural problems (schema, hashes, redaction, timing) refuse the eval.
- `eval-holdout` reuses `report.compute_metrics`/`fmt` (counts beside percentages; `*` for n < 10). Not merged into the
  synthetic tables.

## Tested (`tests/holdout/`)
Schema accept/reject matrix; each quota reported separately; the checked-in empty file reports all quotas with no
structural problem; hash mismatch, missing and orphan logs; credential-shaped log rejected without echoing it;
duplicate ids and source runs; run-before-label, label-edited-after-run, unknown-case, future and pre-fetch labels;
sealed split API and aggregate-only door; baseline behaviour; CLI exit codes and the zero-case message (no numbers);
test ids/rationale absent from output; architecture test (only `eval/` mentions `holdout`; agents/tools/llm/gates
cannot import `eval`; holdout modules have no network, SDK or env access); task wiring. Fixture log text is read at
test time from `captured-verbatim` entries of `generator/error_catalog.json` (invariant 9); no error text was typed.

## Open doubts
- Where does a real-log run come from? A holdout `Source` adapter (stored log -> tools) and a replay path for
  `record` are needed before `runs.json` can be filled by the pipeline; today records would be written by hand or a
  future human-run script. Not built (needs real data and recording).
- Whether `fix` should be restricted to the Tier 3 catalog names. Left free text, since a real-run fix may fall outside
  the six synthetic fixes; the eval compares names exactly, so a typo scores as a miss.
- Layer enum includes L0 and L6 for escalation cases; the L1..L4 quota counts only those layers.
- Logs are decoded as UTF-8 only; fetch must store UTF-8 (GitHub logs may carry a BOM; decide in `holdout-fetch`).
- Run records are single-system (`agent`); an on/off retrieval comparison (N2) will need a variant field (schema bump).
- The seal stops accidental output only: a process that imports the module can reach private attributes, and the files are readable on disk.
- The import closure of `holdout_eval` contains `driftgate.llm.gateway` (through the eval package) though no SDK, HTTP client or dotenv module is loaded; a strict-xfail test records this.
