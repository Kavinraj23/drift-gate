# N5: Static HTML trace report

Branch `mvp2/n5-trace-report`. Not ticked in TASKS.md. No audit KIND, contract, PRD, CLAUDE.md or generator change; no new dependency.

## What was built

- `src/driftgate/report/` (one responsibility: audit entries + saved reports in, HTML strings out).
  - `trace.py`: tolerant JSONL loading (`parse_audit` skips and counts unreadable lines, coerces odd types), grouping into one `Trace` per execution id, the investigation rounds, and `derive_outcome`.
  - `render.py`: `render_trace`, `render_index`, `build_pages` (pure: `{file name: html}`), the escaping rules and `file_name`.
  - `style.py`: the inline CSS (light and dark through `prefers-color-scheme`).
  - `__main__.py`: the CLI behind `python tasks.py trace-report`.
- `python tasks.py trace-report` (offline): with no arguments builds `fixtures/trace_sample/` into `data/report/` (gitignored, regenerable) and prints the paths. `--audit`, `--reports`, `--out` are accepted; this is a second, explicit `ARG_TARGETS` exception beside `approvals`. Every other target still rejects arguments, and HUMAN_ONLY and LIVE_TARGETS are unchanged. argparse rejects any other option (`--serve` exits 2).
- `fixtures/trace_sample/` (`audit.jsonl`, `reports.json`, `README.txt`) and its generator `eval/trace_sample.py` (`python -m driftgate.eval.trace_sample --data data --out fixtures/trace_sample`). The sample comes from the real orchestrator with the scripted model: Tier 0 re-run verified (ex-000384), Tier 3 PR with CI verification (ex-000112), escalation (ex-000744), a Tier 0 proposal the gate downgrades (ex-000605), the `d3-wrong-file` drill with a re-investigation (ex-000863), a Tier 1 case with a refused self-approval, a second person's approval and execution through the N4 flow (ex-000582), and a Tier 1 case denied by a second person (ex-000638). The scenarios' audit logs are concatenated with `seq` renumbered and timestamps (and `expires_at`, same clock) shifted per scenario; nothing else is edited. The generator lives in `eval/` because it reads the labels to pick scenarios; the report itself never touches ground truth (architecture test).

## What a page shows (sections, in order)

Header (execution id, fingerprint, classification, layer, confidence labelled "recorded only", outcome badge, first and last time) and a nav; Hypothesis; Tool calls (per round: id, the audit's one-line summary, how many evidence items cite it); Evidence with citations (each item links to its tool call anchor; an item whose source is not a tool call of this run is flagged `NOT CITED ... dropped in code`; kept/dropped counts from the audit); Proposal and tier (per round, plus the final remediation after the gate); SafetyGate decisions (every `gate_decision` entry with its stage, reason, action, tier, request id, plus the facts the gate was given and the Tier 2 holder proof); Tier 3 review and pull request; Approvals (requested, each approve/deny, refused, expired, with who exactly as recorded and when); Execution and verification; Re-investigation; Final outcome (derived, plus the reasons it stopped); Budget and cost; and the full audit trail in seq order so nothing is hidden.

## What the audit log does and does not hold (checked, not assumed)

Held: the proposal (`stage=agent`) with hypothesis (first 600 chars), tool call ids, a one-line summary per call, evidence kept/dropped counts, stop reason, confidence; gate facts and decisions; approval request, each decision, refusals, expiry; execution, verification, rollback, re-investigation start, Tier 3 diff check and review; why it stopped.

Not held, and rendered as "not recorded" (nothing invented, KINDS and the contract untouched):

- **Evidence items** (finding text, supports). The audit has counts only. They come from the saved `Report.to_dict()` (`reports.json`); without it the page says so.
- **Dropped evidence text.** Never stored anywhere; only the count shows. Uncited items that do appear in a saved report are flagged.
- **Tool results beyond the one-line summary**, and the gate-time deterministic calls (`gate:` ids).
- **A final outcome entry.** There is none; the outcome is derived from the last terminal audit event (`derive_outcome`), which is right for the two-round case. A saved report's `escalation_reason` is shown beside it.
- **Cost and token totals** (only `Report.run`).
- Nothing in the code path today persists `Report.to_dict()` next to the audit log for live runs (logged in BLOCKERS.md).

## Security

All values are untrusted. `esc` redacts (the same credential patterns as the audit writer, so a log produced elsewhere is covered), makes control and bidi/invisible characters visible as `\uXXXX`, caps each value at 2000 characters with a visible marker (bounded regex work first), then `html.escape`. The page has a CSP meta `default-src 'none'; style-src 'unsafe-inline'`, no JavaScript, no external resource, no `url()`/`@import`. The only links are `#fragment` anchors built from integers and relative file names built from a redacted, sanitised, hash-suffixed execution id; no href comes from data. Markup built by the module is a distinct `Html` type, so a raw string cannot pass through unescaped.

## Determinism

Entries are ordered by `(seq, ts)` and executions by id; timestamps are formatted from the logged epoch in UTC; nothing reads a clock. Reversed input produces byte-identical pages (tested).

## Tested (`tests/report/`)

Builds from the sample, every section on every page, each evidence item has a link whose target exists, uncited evidence flagged, approvals with who/when including the refused self-approval and the denial, execution and verification, both re-investigation rounds, budget summary, light/dark, no script/link/img/iframe/form/`url(`/`http(s)://` and only fragment or sibling-file hrefs on every sample page, determinism and input-order independence, empty and partial logs (one entry of each kind, a report without audit entries, damaged lines, wrong types, a 5000-deep payload), hostile strings in every field (script, `onerror`, `javascript:`, entity soup, bidi controls, 100k-character lines, a credential-shaped token) with a tag/attribute allow-list on the parsed output, file names that cannot leave the output directory, the CLI, `tasks.py` argument rules, the committed sample equals what the generator produces, and an architecture test (no network/SDK/dotenv imports, no environment or credentials-file access, no ground truth, no target imports, nothing under `agents/ tools/ llm/ adapters/` imports the report, only the CLI writes files).

## Open doubts

- Evidence text lives only in a saved report; see BLOCKERS.md for who should write `reports.json` on live runs.
- The derived outcome is a reading of the log, not a recorded fact.
- The tool-call "result summary" is whatever the orchestrator audits (tool name plus file or error), not the tool's output.
- The sample's scripted hypotheses and findings (for example "scripted" in the Tier 1 cases) are the scripted double's text, not error text; error strings in the sample come from the dataset.
- `data/report/` is under `data/`, which `tasks.py data` may regenerate; rerun `trace-report` afterwards.
